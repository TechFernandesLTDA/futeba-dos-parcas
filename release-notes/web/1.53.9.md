## Para o usuário

### Headline

- **Criar jogo funcionando novamente!** O erro ao criar jogo a partir do grupo foi corrigido — o campo `xp_processed` estava sendo rejeitado pelas regras de segurança do Firestore.

### Correções

- Removido `xp_processed` do payload de criação de jogo (web) que era bloqueado pelas Firestore rules (PR #3218 endureceu as regras mas os hooks não foram atualizados).
- CSP `connect-src` agora inclui `https://*.firebasestorage.app` — futuro-prova para uploads do Firebase Storage.
- Recurrence engine (Cloud Functions) agora propaga `gender`, `name` e `co_organizers` do jogo pai para os jogos recorrentes filhos.
- Android: `GameRepositoryImpl.createGame` e `updateGame` não enviam mais campos server-managed (`xp_processed`, `validation_*`, `xp_reward_*`, etc.) via client SDK.
- Android: `updateGame` agora usa `SetOptions.merge()` em vez de overwrite completo, evitando deletar campos server-managed.
- Android: `GameDetailViewModel.buildNextGame` reseta todos os campos server-managed ao criar próximo jogo recorrente.
